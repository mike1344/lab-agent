# POC 演示指南（8 分钟）

> 目标：用 8～10 分钟把「业务完整度 + AI/RAG + 工程化」讲清楚，而不是逐页点功能。

## 1. 当前演示数据

本地 MySQL 中已导入「北大计算机系」风格示例数据：

| 数据 | 数量 |
| --- | --- |
| 用户 | 36（18 PKU 学生 + 8 OPS 演示学生 + 2 教师 + 管理员/E2E） |
| 实验室 | 18（17 个演示实验室 + E2E 验收实验室） |
| 设备 | 58 类，覆盖全部 17 个演示实验室 |
| 采购 | 117（32 已验收、34 已到货、51 申请中） |
| 报修 | 21（7 待处理、7 处理中、7 已解决） |
| 实验课程 | 2（含选课名单） |
| 预约 | 255（152 条未来预约；含 97 已通过、54 待审核；其中 51 条 OPS 批量预约） |

重新生成（幂等，会补充未来预约）：

```powershell
cd F:\fastapi项目实战\lab_agent\backend
.\.venv\Scripts\python.exe scripts\generate_pku_seed.py --execute
.\.venv\Scripts\python.exe scripts\seed_ops_demo.py
.\.venv\Scripts\python.exe scripts\verify_seed.py
```

> `seed_ops_demo.py` 会给每个实验室补充 2 类设备（数量按容量配比），生成验收/到货/申请中的采购记录、待处理/处理中/已解决的报修，并用专用 OPS 学生生成未来预约；重复执行不会重复入库。

## 3. 演示脚本

### 0:00–1:00 系统全景

- 打开首页：角色化统计 + ECharts（预约趋势、实验室使用排行、报修分布）。
- 一句话：前后端分离、JWT + RBAC、MySQL、ChromaDB + LangGraph、Docker/CI 完整链路。

### 1:00–2:30 预约主流程（学生）

1. 学生登录 `pku_cs2401_01 / Student123456`。
2. 进入「实验室列表」→ 选择实验室 → 打开「查看周历」→ 点空白时段预填预约。
3. 提交后到「我的预约」查看待审核状态；演示「修改」和「取消」。
4. 提一句冲突校验：时间重叠、课程占用、不可约时段、每周配额、4 小时上限。

### 2:30–3:30 审核与通知（教师）

1. 用 `pku_teacher_li / Teacher123456` 登录。
2. 「预约审核」→ 按实验室筛选 → 通过/拒绝；拒绝需二次密码（电子签名）。
3. 学生端刷新/看通知：WebSocket 实时推送 + 30 秒轮询兜底；邮件可选。

### 3:30–4:30 多级审批流（管理员）

1. `e2e_admin / E2eAdmin123!` 登录 →「审批流配置」。
2. 讲设计：每个实验室 1–8 个节点，按角色或指定人员；中间节点只推进，最后一级才生效；改约自动重走；历史流程节点不可改。
3. 如果时间紧，只展示已有流程/配置页，不现场创建。

### 4:30–5:30 报表、审计与导出（管理员）

- 「报表中心」：机时/费用、按实验室/按用户、双工作表导出。
- 「操作日志」：写操作审计、筛选、导出。
- 「用户管理」：角色、禁用、重置密码。
- 一句话：审计留存 180 天、危险操作二次确认、上传文件可选 ClamAV。

### 5:30–7:00 AI 助手 + RAG（重点）

1. 打开 AI 助手，问：「预约实验室需要遵守哪些规则？」
2. 展示：检索来源（标题/章节/相关度）、工具调用过程、流式回答。
3. 再问：「帮我看看明天下午哪些实验室可约？」展示工具查询。
4. 讲评估（按 `docs/rag-evaluation.md`）：
   - 固定集 40 题；`local`：Recall@4 1.0、MRR 0.9688、引用 0.9375、拒答 0.75；BGE：MRR 0.9844、引用 0.9688、拒答 1.0，平均检索约 33ms。
   - **主动说明**：知识库只有 10 篇小文档、40 题，指标是回归信号，不是通用 benchmark；生成侧 faithfulness 因网关 429 未跑，不伪造。
5. 如果现场模型 429：提前在 `backend/.env` 清空 `OPENAI_API_KEY` 并重启，AI 会走本地知识库/工具模式，仍能演示检索与来源；或临时换可用 Key。

### 7:00–8:00 工程化与收尾

- `scripts/verify.ps1`：ruff + 42 后端测试 + 迁移校验 + RAG 评估 + 前端 7 单测 + 构建。
- GitHub Actions：后端/前端/Docker 三 job；PR 合并前全绿。
- 性能数字（`docs/performance.md`）：单 worker、并发 10 时约 87 QPS、P95 约 186ms；并发 20 约 106 QPS、P95 约 262ms。
- 已知边界：写工具不做强制中断；限流/锁定/WS 是单进程内存实现；BGE 可选不默认安装。
