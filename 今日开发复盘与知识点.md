## 一、AI 助手接入第三方模型（Agnes）

### 知识点 1：OpenAI SDK 兼容第三方 API

**核心原理**：OpenAI 官方 SDK 不仅能调 OpenAI，只要是兼容 OpenAI 格式的 API（Agnes、DeepSeek、通义千问等），改 `base_url` 和 `api_key` 就能直接用。

**代码位置**：`backend/.env`



```
OPENAI_API_KEY=sk-你的key
OPENAI_BASE_URL=https://api.agnes-ai.cn/v1
OPENAI_MODEL=agnes-3.0-flash
```

**代码位置**：`backend/app/ai/agent.py`



```
from openai import OpenAI

client = OpenAI(
    api_key=settings.OPENAI_API_KEY,
    base_url=settings.OPENAI_BASE_URL  # 关键：指向第三方 API
)
```

**为什么不用 Responses API**：

OpenAI 较新的 `client.responses.create()` 是 Responses API，第三方平台兼容性差。标准的 `client.chat.completions.create()` 是行业通用格式，兼容性最好。

### 知识点 2：Chat Completions 工具调用（Function Calling）

**工具定义格式**（`backend/app/ai/tools.py`）：



```
TOOL_SCHEMAS = [
    {
        "type": "function",
        "function": {

            "description": "查询当前开放的实验室以及可用设备",
            "parameters": {
                "type": "object",
                "properties": {},
                "additionalProperties": False
            }

    {
        "type": "function",
        "function": {
            "name": "create_lab_reservation",
            "description": "信息完整并得到用户明确要求后，创建实验室预约",
            "parameters": {
                "type": "object",
                "properties": {
                    "lab_id": {"type": "integer"},
                    "reservation_date": {"type": "string", "description": "YYYY-MM-DD"},
                    "start_time": {"type": "string", "description": "HH:MM"},
                    "end_time": {"type": "string", "description": "HH:MM"},

                },
                "required": ["lab_id", "reservation_date", "start_time", "end_time", "purpose"],
                "additionalProperties": False
            }
        },
        "strict": True
    }
]
```

**调用并解析工具返回**（`run_model_tools` 函数）：



```
response = client.chat.completions.create(
    model=settings.OPENAI_MODEL,
    messages=messages,
    tools=TOOL_SCHEMAS,
    tool_choice="auto",  # 让模型自己决定是否调用工具
)

# 解析工具调用
tool_calls = response.choices[0].message.tool_calls or []
for tool_call in tool_calls:
    name = tool_call.function.name
    arguments = json.loads(tool_call.function.arguments or "{}")
    
    if name == "list_open_labs":
        tool_results.append(list_open_labs(db))
    elif name == "create_lab_reservation":

```

**关键区别**：



* Responses API：`response.output` 遍历，`tool_call.name`

* Chat Completions：`response.choices[0].message.tool_calls`，`tool_call.function.name`

### 知识点 3：流式输出的兼容方案

**问题**：Agnes 的流式 `delta.content` 格式可能和 OpenAI 不完全一致，导致回答攒到最后一次性输出。

**解决方案**：非流式调用 + 后端模拟逐字输出。



```
def stream_answer(message, history, context):
    # 一次性拿到完整回答
    response = client.chat.completions.create(
        model=settings.OPENAI_MODEL,
        messages=messages,
    )
    answer = response.choices[0].message.content or ""
    
    # 模拟流式：每 3 个字符一批 yield 给前端
    for index in range(0, len(answer), 3):
        yield answer[index:index + 3]
```

**为什么这样做**：虽然不是真正的逐 token 流式，但前端效果一样（逐字打出），而且兼容任何 API，不需要担心流式格式差异。

## 二、Pinia 状态管理（对话持久化）

### 知识点 4：为什么对话会丢失

**问题原因**：`messages` 是组件内的局部 `ref`，Vue Router 跳转时组件被销毁，局部状态丢失。

### 知识点 5：Pinia 全局 store 解决

**安装**：



```
npm install pinia
```

**注册**（`main.js`）：



```
import { createPinia } from 'pinia'
app.use(createPinia())
```

**创建 store**（`src/store/chat.js`）：



```
import { defineStore } from 'pinia'
import { ref } from 'vue'
import { streamChatApi } from '@/api/ai'

export const useChatStore = defineStore('chat', () => {
  const messages = ref([{ role: 'assistant', content: '你好，我是实验室 AI 助手...', events: [] }])
  const sending = ref(false)
  let abortController = null

  async function sendMessage(question) {
    if (!question || sending.value) return
    
    // 1. 记录用户消息
    messages.value.push({ role: 'user', content: question, events: [] })
    
    // 2. 创建空白 AI 回复对象
    const assistantMessage = { role: 'assistant', content: '', events: [] }
    messages.value.push(assistantMessage)
    
    sending.value = true
    const currentController = new AbortController()
    abortController = currentController

    try {
      await streamChatApi(
        { message: question, history },
        (eventName, data) => {
          if (eventName === 'token') assistantMessage.content += data.content
        },
        currentController.signal
      )
    } finally {
      sending.value = false
    }
  }

  function stop() {
    abortController?.abort()
  }

  return { messages, sending, sendMessage, stop }
})
```

**组件里使用**（`chat.vue`）：



```
const chatStore = useChatStore()
// 直接读 chatStore.messages，调 chatStore.sendMessage()
// 组件销毁时 store 不销毁，对话数据保留
```

**关键点**：



* SSE 请求放在 store 里，组件跳转不中断请求

* `assistantMessage` 是普通对象，但 push 到 `messages.value` 后就是响应式的，修改 `content` 会触发视图更新

* `setInterval` 轮询通知未读数时，记得在 `onBeforeUnmount` 里 `clearInterval`

## 三、站内通知系统

### 知识点 6：Notification 模型设计

**模型字段设计**（`backend/app/models/notification.py`）：



```
class Notification(Base):
    __tablename__ = "notifications"
    
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"), index=True)
    type: Mapped[str] = mapped_column(String(30), default="system", index=True)
    # type 取值：reservation_result / reservation_reminder / repair_result / system
    title: Mapped[str] = mapped_column(String(200))
    content: Mapped[str] = mapped_column(Text)
    is_read: Mapped[bool] = mapped_column(Boolean, default=False, index=True)
    related_id: Mapped[int | None] = mapped_column(nullable=True)  # 关联业务ID
```

**设计要点**：



* `type` 字段区分通知类型，前端可以按类型做不同展示

* `related_id` 关联业务 ID（比如预约 ID），点击通知可以跳转到对应页面

* `is_read` 加索引，未读数查询很快

### 知识点 7：业务事件触发通知（审核时自动发通知）

**核心代码**（`backend/app/api/reservation.py` 审核接口里）：



```
# 审核完成后，在 db.commit() 之前插入通知
reservation.status = data.status
lab_name = reservation.lab.name
time_text = f"{reservation.reservation_date} {reservation.start_time}-{reservation.end_time}"

if data.status == "approved":
    notif = Notification(
        user_id=reservation.user_id,
        type="reservation_result",
        title="预约审核已通过",
        content=f"你预约的「{lab_name}」{time_text} 已审核通过，请按时到场。",
        related_id=reservation.id,
    )
else:
    notif = Notification(
        user_id=reservation.user_id,
        type="reservation_result",
        title="预约未通过",
        content=f"你预约的「{lab_name}」{time_text} 未通过审核。原因：{data.review_comment or '无'}",
        related_id=reservation.id,
    )
db.add(notif)
db.commit()  # 预约状态和通知一起提交
```

**关键点**：



* 通知和业务操作在同一个事务里，一起 commit，不会出现 "审核成功但通知没发" 的情况

* `with_for_update()` 行锁防止并发问题

## 四、预约修改功能

### 知识点 9：局部更新 Schema

**只允许修改部分字段**（`backend/app/schemas/reservation.py`）：



```
class ReservationUpdate(BaseModel):
    reservation_date: date | None = None
    start_time: time | None = None
    end_time: time | None = None
    purpose: str | None = Field(default=None, min_length=2, max_length=1000)

    @model_validator(mode="after")
    def validate_time_range(self):
        if self.start_time and self.end_time and self.start_time >= self.end_time:
            raise ValueError("结束时间必须晚于开始时间")
        return self
```

**关键点**：



* 所有字段都是 `| None = None`，前端传什么就改什么，不传就不改

* 校验器里要判断 `self.start_time and self.end_time` 都存在才校验，避免只传一个字段时报错



***

### 知识点 10：权限 + 状态双重校验的修改接口



```
@router.put("/{reservation_id}")
def update_reservation(
    reservation_id: int,
    data: ReservationUpdate,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    # 1. 行锁查询
    reservation = db.query(Reservation).filter(
        Reservation.id == reservation_id
    ).with_for_update().first()
    
    # 2. 权限校验：只能改自己的
    if not reservation or reservation.user_id != current_user.id:
        raise BusinessException(code=BizCode.NOT_FOUND, message="预约记录不存在")
    
    # 3. 状态校验：只有 pending 才能改
    if reservation.status != "pending":
        raise BusinessException(code=BizCode.BAD_REQUEST, message="只有待审核的预约才能修改")
    
    # 4. 动态更新字段
    update_data = data.model_dump(exclude_unset=True)  # 只取前端传了的字段
    for field, value in update_data.items():
        setattr(reservation, field, value)
    
    db.commit()
```

`model_dump(exclude_unset=True)` 是关键：只返回前端实际传了的字段，不会把默认 None 覆盖到数据库。

## 五、导出 Excel

### 知识点 11：openpyxl 生成 Excel 文件流

**后端接口**（`backend/app/api/reservation.py`）：



```
from io import BytesIO
from openpyxl import Workbook
from fastapi.responses import Response as FastAPIResponse

@router.get("/export")
def export_reservations(...):
    items = query.all()
    
    wb = Workbook()
    ws = wb.active
    ws.title = "预约记录"
    ws.append(["ID", "预约人", "实验室", "日期", "开始时间", "结束时间", "用途", "状态"])
    
    status_map = {"pending": "待审核", "approved": "已通过", ...}
    for item in items:
        ws.append([
            item.id,
            item.user.full_name,
            item.lab.name,
            str(item.reservation_date),
            str(item.start_time),
            item.purpose,
            status_map.get(item.status),
        ])
    
    # 转成字节流返回
    buffer = BytesIO()
    wb.save(buffer)
    buffer.seek(0)
    
    filename = f"预约记录_{datetime.now().strftime('%Y%m%d_%H%M%S')}.xlsx"
    return FastAPIResponse(
        content=buffer.getvalue(),
        media_type="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        headers={"Content-Disposition": f"attachment; filename={filename}"},
    )
```

### 知识点 13：布尔字段扩展角色

**User 模型加字段**：



```
class User(Base):
    is_superuser: Mapped[bool] = mapped_column(Boolean, default=False)
    is_teacher: Mapped[bool] = mapped_column(Boolean, default=False)  # 新增
```

**权限依赖**（`dependencies/permission.py`）：



```
def get_current_admin(current_user: User = Depends(get_current_user)) -> User:
    """只有管理员"""
    if not current_user.is_superuser:
        raise BusinessException(code=BizCode.FORBIDDEN, message="没有管理权限")
    return current_user

def get_current_staff(current_user: User = Depends(get_current_user)) -> User:
    """管理员或教师都能访问"""
    if not current_user.is_superuser and not current_user.is_teacher:
        raise BusinessException(code=BizCode.FORBIDDEN, message="没有审核权限")
    return current_user
```

**接口里用不同的依赖**：



```
@router.get("")  # 预约列表：管理员和教师都能看
def get_list(_: User = Depends(get_current_staff)): ...

@router.get("/export")  # 导出：只有管理员
def export(_: User = Depends(get_current_admin)): ...
```

## 七、数据库迁移注意事项

### 知识点 15：create\_all 不会更新已有表

**重要坑点**：



```
# main.py 里这行只会创建不存在的表，不会给已有表加新列
Base.metadata.create_all(bind=engine)
```

**后果**：给 User 模型加了 `is_teacher` 字段后，重启后端会报错 `Unknown column 'users.is_teacher'`。

**解决**：手动在数据库执行 SQL：



```
ALTER TABLE users ADD COLUMN is_teacher TINYINT(1) DEFAULT 0 NOT NULL;
```

**经验**：生产环境应该用 Alembic 做数据库迁移，小项目手动执行 ALTER TABLE 就行。
